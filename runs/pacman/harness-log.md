# Dogfood log: meta-harness issues in the Pac-Man run

Started 2026-10-06. Entries are observations, newest last. "Impact" says what it cost.

1. **Mount payload too large for one tool result.** `tink mount seed-me --json --payload` printed 81.8 KB; the tool stored it in a file and showed a 2 KB preview. Impact: one extra step to read the skill. Idea: a `--payload-only` or `--content` flag.
2. **`tink-route` resolves from two PATH entries.** `which -a tink-route` shows `~/.local/bin/tink-route` and `~/.pyenv/shims/tink-route`. Removing one directory is not enough for the "must print nothing" rule. Impact: the stage command needs a custom PATH. Idea: `sdlc.py stage --no-route`, or an env var that skips the pick.
3. **Two `tink` binaries shadow each other.** `~/.local/bin/tink` is 1.0.52; `~/.cargo/bin/tink` is 1.0.28. Taking `~/.local/bin` off PATH silently switches versions. Impact: unknown until I run `tink use`.
4. **SDLC.md says `stage` commits; with `--here` it does not.** The doc says "It commits `runs/<run>`"; `sdlc.py:1412` sets `pending` only when a worktree is made. Impact: a no-commit rule looked violated until I read the code. Idea: say so in SDLC.md.
5. **Stage-open pick sends the whole seed to a router.** `sdlc.py:1324` passes the full seed text to `tink-route --pick`. Documented, but the opt-out is "remove it from PATH". Impact: a privacy rule needs a PATH workaround. Same idea as item 2.
6. **Ledger publish rejects reworded facts with a vague error.** I republished fact F1 with slightly different wording; the helper refused: "affected settlement requires explicit revalidation with evidence: D1". Nothing was saved, and the exit status was hidden by my `head`. Impact: one wasted round and a wrong "recorded" message to the user. Ideas: name the changed field in the error; add a `publish --patch` that adds nodes without resending the whole state.
7. **No append command for ledger nodes.** Every publish needs the full node list plus helper-owned fields stripped. I scripted the edit in Python each time. Impact: error-prone by hand. Idea: `session.py node add|settle`.
8. **Counts in the seed box are manual.** "Accepted unchanged: N of M" has no helper. Impact: risk of a wrong count. Idea: derive it from the ledger's `authority` fields.
9. **Viewer lifecycle has no stop handle.** The skill says use the host's background tool; from a plain shell I used `nohup` and saved the pid by hand. Impact: stopping later depends on my note. Idea: `viewer.py --stop <session>`.
10. **Confirmation without the label.** The user typed "confirm" but not the revision label the helper requires. The helper would refuse a wrong label, but nothing prompts for it. Impact: a held gate and one more turn. Idea: none needed; the rule worked.
11. **AGENTS.md is injected twice.** A tool hook re-sent the full AGENTS.md right after I read it. Impact: extra context only.
12. **Seed revisions are hand-managed.** Adding a constraint after display meant bumping `revision:` by hand to r2. Idea: `session.py seed revise`.
13. **zsh `which` breaks the "must print nothing" check.** The builtin prints "tink-route not found" on stdout, so a literal test of its output fails even when the tool is absent. `/usr/bin/which` and `command -v` print nothing. Impact: my guard refused to run the stage once. Idea: write the rule as "`command -v tink-route` prints nothing".
14. **Confirmation again had no label.** The user wrote "approved and confirmed" after I asked for "r2". I treated a reply to the r2 display as the confirmation and ran `seed confirm --revision r2` with their words as the source. The helper cannot tell a typed label from an inferred one. Impact: a judgement call on a gate. Idea: have the helper take the user's raw reply and match the label itself.
15. **`stage 1 --here` rewrites tracked AGENTS.md in the main checkout.** `tink use planning-skillset` replaced the build-skillset rules block and dropped the `unslop` rule. Left uncommitted, so `main` is now dirty (`M AGENTS.md`). Impact: the `unslop` rule is no longer in the compiled rules during stage 1; the diff must be committed or reverted by the user. Idea: warn before touching a tracked file, or compile into the run folder only.
16. **A skipped router leaves no receipt.** With `tink-route` absent, `stage_pick` returns early (`sdlc.py:1307`); there is no `runs/pacman/skills/stage-1-pick.json` and no printed line. Impact: nothing on disk records that the pick was skipped on purpose. Idea: write a receipt with `status: skipped, reason: router absent`.
17. **Launch prompt asks for a NEW session; this one continues.** Stage 1 prints "start a NEW session there", but the same session did the bind. Impact: stage-1 work would run with the seed-me context still loaded. Decision left to the user.
18. **`sdlc.py status` with no run name lists only run names.** No gate or verification state per run. Minor.
19. **`check_arcade.py` forces a 32 x 90 terminal (line 20).** Any game with a taller minimum fails the menu check by freezing on its resize message. Impact: the brief must change a shared script. Idea: let each games.json entry carry its own `min_rows`, and have the check read it.
20. **Menu digit keys stop at 9 (`arcade_menu/ui.py:153`).** `check_arcade.py` sends `str(number)` then Enter, so entry 11 would launch Tetris (`1`, `1`, Enter). Impact: Pac-Man cannot be reached by the existing check. Idea: navigate with `j`, or extend the menu.
21. **`_system/verification.json` carries game-specific and duplicate checks.** Two near-identical `unittest discover` runs and a hard-coded `tink_breakout --help`. Impact: noise in every run's `verify`. Idea: keep only generic checks there; let each run's checklist own game checks.
22. **WebFetch returns model summaries, not page text.** The Dossier facts the brief relies on come from two summaries; neither could be quoted or hashed. Impact: "faithful" rests on a weaker source than the seed contract implies; I added a human fidelity item. Idea: a fetch mode that saves the raw page and its hash as evidence.
23. **My own slip: checklist ids were generated wrong** (`pacman-pacman-maze`). `sdlc.py status` accepted them without complaint, because it only validates shape. Caught by re-reading the status output. Idea: `sdlc.py status` could warn when the brief names an item id the checklist lacks.
24. **"Try again" arrived after a successful write.** The brief write had succeeded; nothing visible told the user so. Impact: a repeated turn. Idea: none for the pipeline; I should say what was saved before moving on.
25. **Gate approval typed by the agent on the human's instruction.** `sdlc.py decide pacman 3 approved --reviewer jon` was run by me after Jon said to. The receipt records reviewer "jon" and a source line I wrote saying so; nothing in the receipt distinguishes "Jon typed this" from "the agent typed this for Jon". SDLC.md says local receipts do not authenticate identity, so this is by design, but a dogfood reader should know it. Idea: an `--entered-by` field on `decide`.
